# 투자 합의안 계산 규칙

## 반영한 기획

- C는 최대 허용손실(25), 급락 시 행동(15), 비상자금(18), 월 여유자금 비율(17), 목표일까지의 기간(15), 경험·지식(10)의 합이다.
- 비상자금 구간은 `[0,1)`, `[1,3)`, `[3,6)`, `[6,12)`, `[12,∞)`개월이다. 기간은 `[0,12)`, `[12,24)`, `[24,36)`, `[36,60)`, `[60,120)`, `[120,∞)`개월이다.
- 월 여유자금은 `(순소득-필수지출-부채상환)/순소득`이다. 비율을 반올림하지 않고 정확한 금액 비교로 0/4/8/13/17점을 부여한다. 소득 0은 0점이다.
- 경험 응답은 기존 enum을 사용한다: `NONE=0`, `SAVINGS_ONLY=2`, `BOND_FUND_ETF=5`, `STOCK=8`, `HIGH_RISK=10`. 화면 문구는 각각 새 기획의 경험·이해도 설명을 사용한다. `HIGH_RISK`는 여러 자산군 경험과 위험관리 이해를 뜻한다.
- R 기본점수는 `A×0.2+B×0.2+C×0.6`이며 소수점을 보존한다. `centerScore`는 기본점수에 최종 상한을 적용한 R이다. 기존 표시용 `rangeMin/rangeMax`는 정수 범위이며 판정에 사용하지 않는다.
- G−R: `≤-15`는 `LOWER_RISK_SUFFICIENT`, `(-15,-5)`는 `GOAL_INCREASE_POSSIBLE`, `[-5,5]`는 `SUITABLE`, `(5,15)`는 `CONDITIONAL`, `≥15`는 `UNSUITABLE`이다. G가 최종 상한을 넘거나 현재 모델로 달성할 수 없으면 차이와 무관하게 중단한다.
- 허용 시 G 자체를 추천하며 불필요하게 높은 R로 끌어올리지 않는다. 중단 시 추천 점수와 전략은 null이다.
- 조건부·중단 대안은 월 투자금 증가 → 기간 연장 → 목표금액 조정 → 필수/추가목표 분리 → 대안별 달성 가능성 비교 순서다. 비교 수행 결과나 구체적인 조정 금액을 생성하지 않는다.
- LLM은 계산값을 변경하지 않고 설명을 생성한다. 대안 목록·추천점수·전략·상태는 서버 규칙으로 정한다. 모델 미사용/오류 시 규칙 기반 설명을 반환한다.

## 추가 기획이 필요한 부분 (임시 구현)

1. **A·B**: 개인 투자 데이터의 새 산식이 없어 기존 13개 항목 설문 산식을 유지한다. DB 자산 자동 분석은 구현하지 않았다.
2. **최종 상한**: A·B 기존 상한과 C에서 유지되는 손실허용·급락반응·비상자금·투자기간 상한의 최솟값이다. C에서 제거된 설문 항목의 상한은 적용하지 않는다. 새 상한표가 필요하다.
3. **G**: 위험단계별 자산배분, 기대수익·손실 분포, 상관관계, 성공확률 기준이 없어 실제 확률 시뮬레이션은 구현하지 않았다. `calculationMethod=LEGACY_RETURN_BANDS`로 기존 임시 규칙임을 노출한다. `realistic`은 기존 모델 수익률 상한 충족 여부이며 달성 확률이 아니다.

G의 임시 수익률 구간: 필요 연수익률 `≤2%:0~20`, `≤4%:20~35`, `≤6%:35~50`, `≤8%:50~65`, `≤12%:65~80`, `≤20%:80~95`, 그 이상은 중단. 각 구간의 하한을 임시 G로 사용한다. 이 매핑은 검증된 포트폴리오 수익률이 아니며 실제 투자전략 검증을 대체하지 않는다.

필요수익률은 현재금액에 월말 납입을 더하는 월복리 미래가치 식을 BigDecimal 이분법으로 푼다. 무수익 납입으로 달성하면 0%, 현재·월 투자금 모두 0이면 필요수익률 null 및 중단. 표시용 반올림 전에 구간을 판정한다. 기간은 요청 시점부터 목표일까지의 완전한 개월 수이며 1~1200개월을 허용한다.

## API와 DB 변경

- `POST /api/v1/investment-analyses/agreements`는 JWT 인증이 필수다. 토큰 사용자에 대한 실제 `user` 행이 있어야 한다.
- `jointFund`는 `JointRiskAssessmentRequestDTO`로 변경했다. 목표일을 별도로 받지 않고 `goal.targetDate`를 공유한다.
- `goal`은 `targetAmount`, `currentAmount`, `monthlyContribution`, `targetDate` 네 항목만 받는다. 이전 추가입금·인출·세금 필드는 제거되었으므로 프런트도 삭제해야 한다.
- 필수값 누락은 기존 Bean Validation 공통 400 응답으로 거절한다. 프런트에서 해당 필드를 추가 입력받아 재요청하며 AI가 추정하지 않는다.
- `goalId`는 필수이며 요청자가 해당 목표의 연결된 커플 구성원인지 확인한다. 없거나 접근할 수 없는 목표는 동일한 404로 응답한다.
- 기존 `investment_report`에 `goal_id`로 연결하여 실제 개월 수, 추천점수·전략·이유·목표조정안, 상태와 계산방식을 저장한다. 기존 `rationale`, `summary_message`, 목표 입력 스냅샷 컬럼을 재사용한다.
- 요청의 `goal`은 해당 목표에 대한 분석 시나리오다. 분석에 사용한 금액·월 납입액·목표일을 보고서에 보관하며 기존 목표 자체를 수정하지 않는다. 필요수익률을 포트폴리오의 `expected_annual_return`으로 저장하지 않는다.
- 외부 AI 호출 동안 DB 트랜잭션을 유지하지 않는다. 최종 저장은 Spring Data Repository의 쓰기 트랜잭션으로 수행한다.
- 기존 DB에는 [보고서 확장 SQL](investment-report-agreement-migration.sql)을 한 번 적용한다. 기존 보고서 행과 호환되도록 추가 컬럼은 nullable이다. 새 DB의 기준은 `MoAItDB.sql`이다. 실제 DB에는 SQL을 실행하지 않았다.

요청 예시는 [investment-agreement-request.json](investment-agreement-request.json), 실행 방법은 [investment-analysis-test-guide.md](investment-analysis-test-guide.md)를 참고한다.
