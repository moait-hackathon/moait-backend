# 투자 합의안 계산 규칙

## DB 기반 입력과 개인 점수 A·B

요청은 `{"userId": 990001}`만 받는다. `userId`가 속한 `CONNECTED` 커플의 목표를 찾고,
`goal`의 목표·공동 설문과 `investment_account` → `investment_asset`의 개인 보유 자산을 조회한다.
커플당 목표는 1개이며 `ACTIVE` 목표만 분석한다. 탈퇴한 구성원은 제외하고, 연결된 목표가 여러 개면 오류로 응답한다.
A는 `couple.male_id`, B는 `couple.female_id`로 고정하므로 어느 구성원이 요청해도 같은 입력으로 계산한다.

개인 설문은 사용하지 않는다. 각자의 **활성 계좌에 있는 활성 자산의 현재 평가금액**을 기준으로 다음 추정 점수를 계산한다.

```text
A 또는 B = Σ(current_value × 자산 위험점수) / Σ(current_value)
```

금액과 가중합은 BigDecimal로 계산하고, 개인 최종 점수만 HALF_UP으로 정수 반올림한다.
건수·원금·수익률·user.asset은 비중 계산에 사용하지 않는다. 위험점수는 이번 구현의 서비스 규칙이며
검증된 투자 적합성 평가나 개인의 손실 감내 능력을 뜻하지 않는다.

| DB risk_level | 위험점수 |
| --- | ---: |
| VERY_LOW | 0 |
| LOW | 25 |
| MEDIUM | 50 |
| HIGH | 75 |
| VERY_HIGH | 100 |

`risk_level`이 `UNCLASSIFIED`이면 자산 종류에 따라 CASH·DEPOSIT·SAVINGS=0, BOND=25,
STOCK=75, CRYPTO=100을 적용한다. ETF·FUND·PENSION·OTHER는 상품별 위험 차이가 커서
미분류 상태이면 422로 거절하고 위험등급 등록을 요청한다. 명시된 `risk_level`이 종류별 기본값보다 우선한다.

예: HIGH 주식 100만원과 VERY_LOW 예금 300만원이면 `(100×75 + 300×0)/400 = 18.75 → 19점`이다.
같은 주식 100만원만 보유하면 75점이다. 따라서 주식·예금·적금 등의 평가금액 비중 변화가 A·B에 반영된다.

- 평가금액 0인 자산은 비중이 없어 제외한다. 양수 자산이 없는 개인은 0점으로 추정하지 않고 422로 응답한다.
- 음수·null 평가금액, 잘못된 위험등급, 양수 외화 자산은 422이다. 환율 데이터가 없으므로 통화가 다른 금액을 합산하지 않는다. 원화 환산 정책과 데이터가 필요하며 단순히 통화 코드를 바꾸면 안 된다.
- A·B의 응답 `userLimit`, `serviceLimit`, `finalLimit`은 null이다. 보유 비중만으로 개인 손실 허용 상한을 만들지 않는다.
- `R = min(A×0.2+B×0.2+C×0.6, C.finalLimit)`이다. A·B를 없애거나 C로 대체하지 않는다.

## 반영한 기획

- C는 최대 허용손실(25), 급락 시 행동(15), 비상자금(18), 월 여유자금 비율(17), 목표일까지의 기간(15), 경험·지식(10)의 합이다.
- 비상자금 구간은 `[0,1)`, `[1,3)`, `[3,6)`, `[6,12)`, `[12,∞)`개월이다. 기간은 `[0,12)`, `[12,24)`, `[24,36)`, `[36,60)`, `[60,120)`, `[120,∞)`개월이다.
- 월 여유자금은 DB의 `monthly_surplus_band`를 사용한다: `UNDER_0=0`, `UNDER_10=4`, `B10_20=8`, `B20_30=13`, `OVER_30=17`. 저장되어 있지 않은 순소득·필수지출·부채상환 금액을 추정하지 않는다.
- 비상자금은 `UNDER_1M=0`, `M1_3=4`, `M3_6=9`, `M6_12=14`, `OVER_12M=18`이다. 실제 개월 수를 임의 생성하지 않는다.
- 경험은 DB enum을 사용한다: `NONE=0`, `SAVINGS_ONLY=2`, `ETF_ONLY=5`, `STOCK_ALL=8`, `MULTI_ASSET=10`.
- R 기본점수는 `A×0.2+B×0.2+C×0.6`이며 소수점을 보존한다. `centerScore`는 기본점수에 최종 상한을 적용한 R이다. 기존 표시용 `rangeMin/rangeMax`는 정수 범위이며 판정에 사용하지 않는다.
- G−R: `≤-15`는 `LOWER_RISK_SUFFICIENT`, `(-15,-5)`는 `GOAL_INCREASE_POSSIBLE`, `[-5,5]`는 `SUITABLE`, `(5,15)`는 `CONDITIONAL`, `≥15`는 `UNSUITABLE`이다. G가 최종 상한을 넘거나 현재 모델로 달성할 수 없으면 차이와 무관하게 중단한다.
- 허용 시 G 자체를 추천하며 불필요하게 높은 R로 끌어올리지 않는다. 중단 시 추천 점수와 전략은 null이다.
- 조건부·중단 대안은 월 투자금 증가 → 기간 연장 → 목표금액 조정 → 필수/추가목표 분리 → 대안 비교 순서다. 서버가 구체적인 금액·증액·개월 수를 계산하고 LLM에 전달한다. 확률 시뮬레이션을 수행한 것으로 표현하지 않는다.
- LLM은 계산값을 변경하지 않고 설명을 생성한다. 대안 목록·추천점수·전략·상태는 서버 규칙으로 정한다. 모델 미사용/오류 시 규칙 기반 설명을 반환한다.

## 구체적인 목표 조정안

모든 상태의 `alternatives`에 계산된 수치를 포함한다. 자금이 충분하면 납입액 감액·기간 단축·목표 상향도 제시한다. `UNSUITABLE`도 LLM 호출을 수행하여 조정안을 요약·설명한다. AI 미설정/실패 시에도 같은 수치가 반환된다. 응답 형식은 기존 `List<String>`을 유지하고 `investment_report.goal_adjustments`에 그대로 저장한다.

- 연수익률은 기존 임시 G 구간과 일관되게 `min(R, 최종상한)`으로 정한 **시나리오 가정**이다: R=0은 0%, (0,20)은 2%, [20,35)는 4%, [35,50)는 6%, [50,65)는 8%, [65,80)는 12%, 80 이상은 20%. 검증된 포트폴리오 기대수익률이나 수익 보장이 아니다.
- 연복리 가정에 대응하는 월 성장계수를 BigDecimal 이분법으로 구한다. 현재금액과 매월 말 납입액으로 미래가치를 계산하며 세금·수수료는 제외한다.
- 납입액 조정: 목표금액·기간을 유지하는 월 납입액을 계산하고 1원 단위 올림, 기존 납입액 대비 증액을 표시한다.
- 기간 조정: 현재금액·납입액을 유지하며 목표에 도달하는 최소 완전 개월 수를 탐색한다. 목표일은 기존 목표일에 추가 개월 수를 더한다. 총 1200개월 안에 도달하지 못하면 기간 연장만으로 부족하다고 표시한다.
- 목표금액 조정: 현재 기간·납입액에서 예상금액을 1원 단위 버림하여 목표 감액과 차액을 제시한다. 예상금액이 0원이면 양수 목표에 필요한 자금 마련을 먼저 안내한다.
- 목표 분리: 예상금액과 부족액을 표시하지만 실제 필수목표 금액을 임의로 결정하지 않는다. 증액안의 실제 납입 가능 여부는 사용자의 지출·여유자금과 별도 확인해야 한다.

예: 목표 2억원, 현재 1억원, 월 300만원, 기간 23개월, R=40일 때 **연 6% 가정**으로 월 **3,632,796원(632,796원 증액)**, 또는 **4개월 연장(총 27개월)**, 또는 목표를 **184,639,204원으로 감액**하는 비교안을 반환한다. 실제 요청값이 바뀌면 수치도 달라진다.

## 추가 기획이 필요한 부분 (임시 구현)

1. **A·B**: 위 평가금액 가중 위험점수를 사용한다. 위험등급 수치와 미분류 자산 기본값은 명시적인 서비스 가정이며 추후 검증·조정할 수 있다. 외화 환산은 미구현이다.
2. **최종 상한**: C의 손실허용·급락반응·비상자금·투자기간 상한 중 최솟값이다. 개인별 상한이 필요하면 별도의 손실허용·재무여력 데이터가 필요하다.
3. **G**: 위험단계별 자산배분, 기대수익·손실 분포, 상관관계, 성공확률 기준이 없어 실제 확률 시뮬레이션은 구현하지 않았다. `calculationMethod=LEGACY_RETURN_BANDS`로 기존 임시 규칙임을 노출한다. `realistic`은 기존 모델 수익률 상한 충족 여부이며 달성 확률이 아니다.

G의 임시 수익률 구간: 필요 연수익률 `≤2%:0~20`, `≤4%:20~35`, `≤6%:35~50`, `≤8%:50~65`, `≤12%:65~80`, `≤20%:80~95`, 그 이상은 중단. 각 구간의 하한을 임시 G로 사용한다. 이 매핑은 검증된 포트폴리오 수익률이 아니며 실제 투자전략 검증을 대체하지 않는다.

필요수익률은 현재금액에 월말 납입을 더하는 월복리 미래가치 식을 BigDecimal 이분법으로 푼다. 무수익 납입으로 달성하면 0%, 현재·월 투자금 모두 0이면 필요수익률 null 및 중단. 표시용 반올림 전에 구간을 판정한다. 기간은 요청 시점부터 목표일까지의 완전한 개월 수이며 1~1200개월을 허용한다.

## API와 DB 변경

- `POST /api/v1/investment-analyses/agreements`는 스펙상 JWT 토큰 인증이 필요한 API이다. (단, 개발 테스트 편의를 위해 `SecurityConfig`의 `PUBLIC_ENDPOINTS`에 포함되어 있어 무인증 접근도 허용되어 있다). 로그인 여부에 따른 별도 서버 분기는 없다.
- 요청 필드는 양수 `userId` 하나다. 기존 `goalId`, `personA`, `personB`, `jointFund`, `goal` 입력은 제거한다.
- `goal.target_amount`, `current_amount`, `monthly_investable_amount`, `target_date`를 사용한다. 목표까지 기간은 호출 시점부터 다시 계산하며 저장된 `investment_period_months`, `risk_profile_score`는 사용하지 않는다.
- userId 누락·0·음수는 공통 400, 연결된 공동 목표 없음은 404, DB 필수값 누락·잘못된 값·온보딩 미완료·자산 부족은 `ANALYSIS_DATA_INCOMPLETE` 422로 응답한다. 목표일이 현재보다 1개월 이상 100년 이내가 아니면 기존 400이다. 누락 데이터는 온보딩 또는 자산 등록·동기화로 보완한 뒤 같은 userId로 재요청한다.
- 현재 공개 설정에서는 요청 userId와 JWT 주체의 일치 여부를 검사하지 않는다. 운영 인증·소유권 검증은 별도 적용이 필요하다.
- 기존 `investment_report`에 `goal_id`로 연결하여 실제 개월 수, 추천점수·전략·이유·목표조정안, 상태와 계산방식을 저장한다. 기존 `rationale`, `summary_message`, 목표 입력 스냅샷 컬럼을 재사용한다.
- DB에서 읽은 분석 당시 금액·월 납입액·목표일을 보고서에 보관하며 기존 목표 자체를 수정하지 않는다. 필요수익률을 포트폴리오의 `expected_annual_return`으로 저장하지 않는다.
- 입력 로더의 읽기 전용 REPEATABLE_READ 트랜잭션에서 목표와 두 사람의 자산을 2회 조회하여 DTO로 복사한다. 외부 AI 호출 동안 DB 트랜잭션을 유지하지 않는다. 최종 저장은 Spring Data Repository의 쓰기 트랜잭션으로 수행한다.
- 기존 DB에는 [보고서 확장 SQL](investment-report-agreement-migration.sql)을 한 번 적용한다. 기존 보고서 행과 호환되도록 추가 컬럼은 nullable이다. 새 DB의 기준은 `MoAItDB.sql`이다. 실제 DB에는 SQL을 실행하지 않았다.

요청 예시는 [investment-agreement-request.json](investment-agreement-request.json), 실행 방법은 [investment-analysis-test-guide.md](investment-analysis-test-guide.md)를 참고한다.
